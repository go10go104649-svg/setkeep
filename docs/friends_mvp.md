# フレンドMVP

一般版ホーム下部のカードから、フレンドのトレーニング詳細と既存3D筋肉ヒートマップを開く。いいねは1ユーザー1件、コメントは1〜140文字。自分のいいねとコメントは取り消せる。フレンド設定で表示名を登録し、相手から受け取ったUUID招待コードで申請する。相手だけが承認でき、双方が申請取消・拒否・解除できる。

公開は初期値「非公開」。設定画面で「承認済みフレンドのみ」を選択し保存した場合、既存履歴も含め日時・種目・セット・所要時間を共有する。場所・メモ・体重・TRAINER識別情報は送信しない。共有にPremium権限は不要。アカウントとSupabase接続は必要。

共有は `friend_workouts` の専用スナップショット。通常 `workouts` / Premiumバックアップ / TRAINER認可・同期は変更しない。記録保存・編集・削除・Undo時にローカル保存後、共有を直列で更新する。更新は1トランザクションでupsert＋削除、同じ日時のID・リアクションを保持する。削除時はリアクションもcascade。履歴の初期ロード完了前に空の共有スナップショットを送らない。ホームの読み込み・更新、設定保存で再試行する。オフラインの記録変更はローカルへ残り、オンラインで更新するまで以前の共有が残る可能性がある。

非公開に戻した場合、RLSが既存共有・リアクションへのフレンドアクセスを直ちに拒否する。フレンド解除も同様。スナップショット自体は保持し、再公開で履歴を再同期する。すでに画面上に表示済みの情報は、画面更新時に再認可される。ホームは直近10カード、詳細/ヒートマップはサーバーの直近最大1000件を対象とする。

追加は5テーブル（profiles/connections/workouts/likes/comments）とRLS・6関数。既存記録テーブルへの変更はない。Authユーザー削除はsocialデータへcascade。公開同意後に履歴が複製されるため、DB容量とプライバシー説明を確認する。旧アプリと互換性がある。migration未適用の場合、フレンド欄は読込失敗・再試行表示となり通常記録は維持される。

ロールバックはまずフレンド機能を外したアプリへ戻し、socialテーブルのauthenticated権限とRPC実行権限をrevokeしてアクセスを停止する。データ保持が必要ならテーブルを残す。削除する場合はsocialデータを退避した後、5テーブルと6関数のみを依存順で削除する。通常 `workouts`、Authユーザー、TRAINERテーブルは削除しない。復旧後は権限とRLSテストを再確認する。
